# UI Audit — Baztit Tech Landing Page

**Дата:** 14 марта 2026  
**Цель:** Выявить визуальные и UX-проблемы, составить конкретный план исправлений.

---

## 1. НАВИГАЦИЯ — «криво»

### Проблемы
| # | Проблема | Причина |
|---|----------|---------|
| 1.1 | Ссылки в навбаре слишком большие / «раздутые» | Глобальное правило `a, button { min-height: 44px; min-width: 44px }` — каждый элемент занимает минимум 44×44px, из‑за чего текст-ссылки выглядят как огромные кликабельные зоны |
| 1.2 | На десктопе 7 пунктов меню — переполнение или перенос | `flex-wrap: wrap` + `gap: 8px` — при ширине ~900–1100px пункты переносятся на вторую строку, навбар «ломается» |
| 1.3 | Кнопка CTA в навбаре визуально сливается с обычными ссылками | Нет достаточного визуального разделения между ссылками и CTA |
| 1.4 | На мобиле только гамбургер — при открытии меню всё в столбик | Ок, но пункты могут быть слишком длинными и занимать много места |

### План исправлений
- [ ] **1.1** Убрать глобальные `min-height/min-width` для `a, button` — применить только к кнопкам и CTA. Для нав-ссылок использовать `padding` вместо min-size.
- [ ] **1.2** Сократить пункты меню: объединить «How We Work» + «Experience» → «Work» или «Cases», убрать дубли. Целевое число: 4–5 пунктов + CTA.
- [ ] **1.3** Добавить `gap` между группой ссылок и CTA (например `margin-left: auto` + `gap`), визуально отделить кнопку.
- [ ] **1.4** На мобиле — уменьшить размер шрифта в выпадающем меню, добавить разделители.

## 2. ГЛАВНАЯ СТРАНИЦА — «много всего лишнего»

### Проблемы
| # | Проблема | Детали |
|---|----------|--------|
| 2.1 | **11 секций** — страница очень длинная | Hero, Ticker, Pain, About, How We Work, Cases, What We Build, Solutions Preview, Team, Offer, Comparison, Contact |
| 2.2 | Дублирование контента | Scarcity («1 spot available») — в Hero и в Offer. «Prototype first» повторяется в Hero, How We Work, Offer, Contact |
| 2.3 | Solutions Preview + What We Build частично пересекаются | «Ready-Made Solutions» в bento и отдельный блок «Already built» — избыточно |
| 2.4 | Слишком много текста в Hero | Tag + H1 + typewriter (длинный подзаголовок) + 2 CTA + 4 числа + scarcity = 7 блоков. Перегружено |
| 2.5 | Pain — 6 карточек | Много. Можно сократить до 3–4 ключевых болей |
| 2.6 | About — «стена текста» | 3 абзаца + 4 пункта + 3 progress bars. Тяжело читать |
| 2.7 | Team — 4 карточки, включая «UX Partner Team» | Последняя карточка почти пустая — «Brought in on projects that need them» |

### План исправлений
- [ ] **2.1** Объединить секции: Pain + About → «The Problem & Why Us»; Offer + Comparison → «Our Promise»; Solutions Preview встроить в What We Build или сократить до 2 карточек + ссылка.
- [ ] **2.2** Scarcity оставить только в одном месте (Offer или Hero). Убрать повторы «prototype first» — оставить в Hero и Contact.
- [ ] **2.3** Убрать отдельный Solutions Preview или сделать его компактным (2 карточки + «View all»).
- [ ] **2.4** Hero: убрать typewriter или сократить до 1 строки. Числа — оставить 2–3 ключевых. Scarcity — один раз.
- [ ] **2.5** Pain: оставить 3–4 карточки, объединить похожие боли.
- [ ] **2.6** About: сократить до 1–2 абзацев + 4 буллета. Progress bars — опционально убрать или заменить на иконки.
- [ ] **2.7** Team: 3 карточки (основная команда). UX Partner — одной строкой в футере или в About.

## 3. БЛОКИ — «сильно большие»

### Проблемы
| # | Проблема | Значения |
|---|----------|----------|
| 3.1 | Hero занимает весь экран | `min-height: 100vh` — на высоких мониторах огромное пустое пространство |
| 3.2 | Секции без max-width | Контент растягивается на всю ширину (с padding 16–24px). На широких экранах текст слишком широкий |
| 3.3 | `margin-bottom: 48px` между секциями | `--space-xxl` — много «воздуха», страница кажется разреженной и длинной |
| 3.4 | Карточки с `padding: 24px` | glass-card везде одинаковый — визуально тяжело |
| 3.5 | Case cards: `min-width: 380px` | Карточки очень широкие, горизонтальный скролл длинный |
| 3.6 | H2 заголовки: `clamp(28px, 4vw, 52px)` | На десктопе 52px — крупно, но не критично. Проблема скорее в количестве секций |

### План исправлений
- [ ] **3.1** Hero: `min-height: 85vh` или `min-height: 600px` + `max-height: 90vh` — не растягивать на 4K.
- [ ] **3.2** Обернуть контент секций в `.container` с `max-width: 1140px` (уже есть в CSS, но не используется в HTML).
- [ ] **3.3** Уменьшить `margin-bottom` секций до `--space-xl` (32px) или `--space-lg` (24px).
- [ ] **3.4** Разделить карточки: крупные (featured) — `padding: 24px`, обычные — `padding: 16px`.
- [ ] **3.5** Case cards: `min-width: 300px` или 320px — компактнее.
- [ ] **3.6** H2: `clamp(24px, 3.5vw, 42px)` — чуть меньше.

## 4. ВИЗУАЛЬНЫЕ ПРОБЛЕМЫ

### Проблемы
| # | Проблема | Детали |
|---|----------|--------|
| 4.1 | Эмодзи в карточках (💸, 🔁, 🧩, ⏱️, 🤖, 🔌) | Выглядят непрофессионально. Заменить на иконки (SVG) или убрать |
| 4.2 | Section tags («// the problem», «// why we're different») | Повторяющийся паттерн — можно оставить, но уменьшить размер и контраст |
| 4.3 | Ticker — ярко-жёлтая полоса | `background: var(--accent)` — режет глаза. Сделать приглушённее или уменьшить высоту |
| 4.4 | Glass-card hover: `translateY(-6px)` | Все карточки «подпрыгивают» — слишком однообразно, отвлекает |
| 4.5 | Comparison table — без визуального акцента | Таблица сливается с фоном. Добавить лёгкий фон для «us» колонки |
| 4.6 | Footer — мало структуры | Всё в одну кучу. Разделить на колонки: Brand | Links | Contacts |

### План исправлений
- [ ] **4.1** Заменить эмодзи на SVG-иконки или простые символы (●, →). Либо убрать.
- [ ] **4.2** Section tags: `font-size: 10px`, `opacity: 0.8`.
- [ ] **4.3** Ticker: `background: rgba(232, 255, 71, 0.15)` или `color: accent` с тёмным фоном.
- [ ] **4.4** Hover: только `border-color` + лёгкий `box-shadow`, без translate. Либо применять translate только к featured-карточкам.
- [ ] **4.5** `.col-us` — добавить `background: var(--accent-dim)`.
- [ ] **4.6** Footer: grid 3 колонки на десктопе.

- [ ] **5.3** Добавить `margin-bottom` между tag → h2 → контент для чёткой иерархии.
